## 三、回复正文（定稿）

```
@宋君毅 看到你 C2 的评审，第 1、2 条我上个月刚踩过一模一样的坑，把走通的路径贴给你 👇

1）仓库「没有 README」通常不是没写，而是位置/大小写不对
评审是从仓库根目录扫的。确认 README.md 在根目录（不是放在 docs/ 里），且文件名大小写完全一致（是 README.md，不是 readme.md）。我上次就是放进了子目录，被判 hasReadme=false。

2）本机没有 LaTeX 引擎，也能证明「可独立编译」
这条路我走通过，两条：
· 省事：传 Overleaf，xelatex 一次过，把编译出的 PDF + 编译日志一起放进仓库；
· 本地：如果 github 拉不动（我这边 curl 直接返回 HTTP:000——那是整个域名不可达，不是 404，改 URL 没用），可换清华 TUNA 镜像装便携版 MiKTeX。两个坑提前避开：① 便携装里没有 xelatex.exe，要 cp miktex-xetex.exe xelatex.exe；② 报 formats.ini could not be found 时，跑 initexmf --register-root=<安装目录> + --update-fndb + --dump=xelatex 就能修。
· 最后按 xelatex → bibtex → xelatex → xelatex 四遍收敛，把 PDF 和 log 一起提交——这样「可编译」就从自述变成了可核查的证据。

3）文献 9 → 15~20 篇
我当时也发现 AI 报的元数据有错（一篇题名记错、一篇卷期页模糊）。做法是逐条去 arXiv/Nature/DBLP 核对，查不到一手出处的宁可删掉，最后留 16 条、正文引用率 100%、无孤立条目，评审这点给了正面评价。

@宋君毅 你现在卡在哪一步——是仓库 README 检不出来，还是本地一直没跑通编译？把报错贴出来，我看看能不能直接给你定位。
```
