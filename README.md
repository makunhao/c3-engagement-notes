## 三、自检脚本用法

脚本有**两种模式**，按输入自动切换（**永远不要用"帖子门槛"去卡"追踪表"**——那是度量误判）：

```bash
# 模式 A：帖子要素预检（默认扫 posts/ 目录）
python tools/check_engagement.py                    # 扫 posts/
python tools/check_engagement.py posts/短帖-群聊版.md

# 模式 B：互动追踪表完成度检查（按文件名/内容自动识别）
python tools/check_engagement.py 互动追踪表.md
```

**模式 B 的输出长这样**（它检查的是"四栏是否留痕 + 闭环是否形成"，而不是帖子要素）：

```
文件：互动追踪表.md
识别为：互动追踪表（检查「四栏是否留痕」，而非帖子要素）
  第一节 我发出的      ：已发出 5 行 / 未发出 10 行
  第二节 我回应别人的  ：已填写 3 行
  第三节 别人回应我的  ：0 行有真实回应  ← 验收要点「被至少 1 位同学/教师回应」
  第五节 零回应记录    ：5 轮已留痕
  [√] 第一节 ≥5 行有日期的记录
  [√] 第二节 ≥3 行（主动回应）
  [×] 第三节 ≥1 行（被回应）——验收要点，没有就不算闭环
  ⚠ 未闭环：缺「被回应」记录。这一栏由他人决定，如实标注为 0 即可，不要伪造。
```

**类型感知的硬门槛**（仅模式 A，帖子顶部用 `<!-- type: question|share|feedback -->` 声明）：

| 类型 | 硬门槛 |
|---|---|
| 提问类 | 上下文 + 已尝试 + 具体卡点 |
| 分享/结论类 | 上下文 + 证据/数字 + 可执行结论 |
| 回馈群结论类 | 上下文 + 证据/数字 + 可执行结论 |

会检测负面信号（`+1`、`顶`、纯表情等灌水模式）。

**还会做「媒介适配检查」**（这条规则是用一次真实失败换来的）：

```
  媒介适配（群聊单屏约 200–400 字）
    ⚠ 偏长  最长的块 #1：2197 字  (约 7 屏)
  ⚠ 存在 2197 字的块——群聊里大概率没人读完。
     建议：拆成 ≤200 字的短帖（先发钩子，有人接话再展开长文）
```

汇总行会标 `长 / 短`：`帖03 ... (2887 字, 最长块 2197 长)` 表示**不适合直接发群**；
`短帖-群聊版.md ... (2854 字, 最长块 449 短)` 表示**可发群**。

> **发布前请自己加一问："这条在对方手机上占几屏？"** 超过 1 屏就拆。
